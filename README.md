## blind-sqli

**做了什么**:不借助 sqlmap,用二分查找从本地一个故意有漏洞的 Flask 登录页面里提取出完整密码。

| 项目 | 说明 |
|---|---|
| 靶场 | Flask + SQLite,字符串拼接导致注入 |
| 攻击 | 布尔盲注 + 二分查找 |
| 工具 | 纯 Python + requests,零第三方安全工具 |
| 结果 | 提取出 20 位密码,约 140 次请求 |

### 核心思路

整个攻击被压缩成一个函数:

```python
def is_true(expr) -> bool:
    # 把 expr 拼进 SQL,看服务器返回"登录成功"还是"登录失败"
```

之后就是纯算法问题:**一个未知字符串,只能通过"是/否"提问,用二分还原它。**

### 为什么用二分

可打印 ASCII 有 95 个,线性试需 ~95 次请求。
一次"是/否"回答只提供 **1 bit** 信息,而 log₂(95) ≈ **6.6 bit**。
二分只需 ~7 次,恰好达到信息论下界。

### 踩过的坑

- `#` 是 MySQL 注释符,SQLite 只认 `-- `(**后面必须有空格**)
- `length((SELECT ...))` 测的是**子查询返回的值**的长度,不是 SQL 文本长度
- `substr` 越界返回空串,`unicode('')` 为 `NULL`,比较会**静默失效** → 必须先查长度
- 网页/终端里看不到真实 SQL 时无法调试 → 靶场必须 `print("[SQL]", sql)`

### 运行

```bash
pip install flask requests
python target.py     # 终端 A:靶场,保持运行
python exploit.py    # 终端 B:攻击脚本
```

> ⚠️ `target.py` 是**故意有漏洞**的,仅供本地 `127.0.0.1` 学习,不要部署到公网。
